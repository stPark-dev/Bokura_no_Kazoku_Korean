# 사용자 결정 기록

각 결정은 ID로 참조한다. 바뀌면 지우지 않고 상태를 `superseded`로 두고 새 항목을 단다.

## D1 번역·검수 담당 — adopted (2026-11-11)
- 질문: 초벌 번역과 검수를 누가 하는가.
- 결정(사용자): **초벌 번역과 검수를 모두 Claude가 맡는다** (GPT 검수 없음).
- 영향: 검수 상태는 Claude 검수 기준으로 기록한다. 사람이 문장별로 검수하지 않았다는 점은 배포 안내에 밝힌다.
- 재검토: 사용자가 사람 검수나 외부 검수를 추가하기로 할 때.

## D2 한글화 범위 — adopted (2026-11-11)
- 질문: 그림 글자·동영상까지 포함할지.
- 결정(사용자): **처음부터 전부 한글화를 목표로 한다** — 대사·메뉴·데이터 텍스트, 그림 글자(앨범 라벨·표지·타이틀·미니게임 등), 동영상 속 글자까지.
- 영향: 그림 글자 카탈로그와 PSS 동영상 조사가 필수 작업이 된다. 범위를 줄이려면 근거를 들어 다시 결정을 받는다.
- 예외 후보(결정 필요 시 다시 묻기): PS2 BIOS가 표시하는 메모리 카드 저장 이름 — BIOS 글꼴에 한글이 없음.

## D3 이름 입력 — adopted (2026-11-11)
- 질문: 이름 입력을 어떻게 한글화할지.
- 결정(사용자): **한글 조합 입력이 가능해야 한다** (초성·중성·종성을 조합해 임의의 한글 이름 입력).
- 영향: 이름 입력 화면 코드 훅/재설계가 필요하다. 입력 가능한 글자를 조합해 만들 수 있어야 하므로, 폰트에 들어갈 한글은 대사에 쓰인 글자만이 아니라 **KS X 1001 한글 2,350자 이상**(또는 조합 가능한 전체)을 확보해야 한다. 이름 뒤 조사 처리도 같이 설계한다.

## D4 제목 — adopted (2026-11-11)
- 결정(사용자): 한국어 제목은 **우리들의 가족**.

## D5 세로쓰기 대사 창 — adopted (2026-11-11)
- 질문: 원작의 세로쓰기 대사 창을 한국어에서도 유지할지, 가로로 바꿀지.
- 결정(사용자): **세로쓰기를 반드시 유지한다.**
- 영향: 실행 파일의 배치 코드는 건드리지 않는다. 세로쓰기 문장부호 치환표(`FONT.XAP/vcode.txt`)는 한국어 문장부호(「」, …, ー 등)에 맞게 유지·보강한다. 세로 창의 줄 길이(글자 수) 한도를 따로 측정해 번역 길이 제약으로 쓴다.

## D6 이름 입력 방식 — adopted (2026-11-11)
- 질문: 이름 입력을 데이터만 바꾼 음절 선택판으로 할지, 실행 파일을 고쳐 자모 조합 입력으로 할지.
- 결정(사용자): **자모 조합 입력** (ㄱ→ㅏ→ㄴ 순서로 눌러 '간'을 만드는 방식, 받침·되돌리기 포함). D3를 구체화한 결정.
- 기술 제약(사실): 게임 텍스트는 SJIS 2바이트 코드라, 기존 기호 영역을 빼면 쓸 수 있는 코드가 약 1만 개뿐이다. 현대 한글 11,172자를 다 담을 수 없으므로 **조합 결과는 KS X 1001 한글 2,350자로 제한**한다. 범위 밖 음절(예: 똠, 햏)은 조합되지 않게 처리한다.
- 영향: `CMenuInputKanji`(이름 입력) 코드를 역공학해 입력 처리에 훅을 넣는다. 자모 → 음절 조합 표(KS 2,350자 역참조)를 실행 파일 메모리에 둔다.
- 재검토: 훅 위험이 지나치게 크다고 판명되면 근거와 함께 음절 선택판(데이터 전용)을 다시 제안한다.

## D7 인명 표기 — adopted (2026-11-11)
- 질문: 대사·이름 목록의 일본 인명(별명 チコ·モック, 기본 이름 桜田 咲太郎 등)을 음역할지 한국 이름으로 바꿀지.
- 결정(사용자): **일본식 음역 유지** (치코, 모크, 사쿠라다 사쿠타로 식). 배경(도쿄)·풍습은 그대로 둔다.
- 영향: 기본 이름·이름 목록(`NAMEDB`)도 음역. 음역 표기는 국립국어원 일본어 표기법을 기본으로 하고, 별명은 용어집에 결정 ID로 기록한다.

## D8 입학시험 퀴즈(MINIG5) — adopted (2026-11-11)
- 질문: 일본어 한자 읽기·뜻·틀린 말 고르기 289문제를 어떻게 옮길지 (폰트에 한자 없음).
- 결정(사용자): **한국어 문제로 새로 출제.** 같은 3유형·난이도(A/B/C)·문항 수·정답 위치 형식을 유지하고, 맞춤법·어휘·낱말 뜻 등 한국어 시험으로 바꾼다.

## D9 동영상 글자 — adopted (2026-11-11)
- 결정(사용자): **제목만 한글, 크레딧 유지.** 오프닝 제목 `ぼくらのかぞく`과 엔딩 15개의 제목 카드만 한글로 바꾸고, 스태프 크레딧(이름·직함)은 원본 유지(승인된 예외).

## D10 소개 배경 사진의 간판 — adopted (2026-11-11)
- 결정(사용자): `MENU.XAP/inf*` 64장의 간판 등 배경 속 일본어는 **그대로 둔다**(승인된 예외, 도쿄 배경 유지 D7과 같은 취지).

## D11 윤문 범위 — adopted (2026-11-12)
- 배경(플레이 테스트): 메뉴 선택지(「자동으로 다음 해로 / 입력을 기다려 다음 해로」 등)가 일본어 구조를 그대로 옮긴 번역투.
- 결정(사용자): **메뉴·시스템 텍스트를 먼저** 자연스러운 한국어로 다시 다듬고, 대사(4,478블록)는 그 다음 별도 패스로 윤문한다.
- 원칙: 뜻·정보·말투(존댓말/반말)·고유명사(D7)는 유지하고, 일본어 어순·직역 조사·「~의」 남용·한자어 직역을 한국 게임 UI에서 쓰는 표현으로 바꾼다.

## D12 가로 창 칸 넘침 — adopted (2026-11-12)
- 배경: 가로 창에서 ASCII 공백이 한 칸(글자 폭)으로 그려지고, 번역문이 원문보다 길어 창을 벗어남(MEMO 줄, 책 소개, 「게임을 계속하겠습니까?」).
- 결정(사용자): **공백을 반 칸으로**(실행 파일 글자 그리기에 훅) + **원문 줄 너비를 넘는 줄은 더 짧고 자연스럽게 고친다.** 한글 글자 크기는 원작 그대로 둔다.

## D13 이미지 수작업 교체 — adopted (2026-11-12)
- 결정(사용자): 글자가 든 원본 이미지를 `work/gfx_export/`에 PNG로 추출하고, 사용자가 외부 도구(GPT)로 고친 PNG를 `work/gfx_import/`에 같은 경로·크기로 넣으면 빌드가 팔레트를 다시 만들어 넣는다.
- 저장소: 원본 게임 그림의 2차 저작물이므로 **공개 저장소에 커밋하지 않는다.** 빌드 매니페스트에 넣은 파일의 SHA1을 기록해 재현성을 보장한다.

## D14 정식 배포 v1.0.0 — adopted (2026-11-12)
- 근거: 사용자가 PCSX2에서 1단계 모드(아이 3명)를 엔딩까지 플레이하며 화면을 확인했고, 그 과정의 결함(학교 이름 26바이트, 앨범 「春」, 상태 창 라벨 등)을 고쳤다.
- 결정(사용자): 전 단위(대사 4,478 · 시스템 메시지 60 · 시스템 텍스트 2,461)를 `reviewed` → `distribution_eligible`로 올리고 `--policy release`로 v1.0.0을 만든다. 배포처는 동굴팩(사용자가 직접 업로드).
- 남는 한계: 2·3단계 모드(아이 4·6명)의 고유 화면, 미니게임 일부, 실기는 화면 확인 전. 사람의 문장별 검수는 하지 않음(안내문에 명시). 제보를 받아 1.0.x로 고친다.
