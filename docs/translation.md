# 번역 규칙 (대사 `.mes`)

## 산출물
- `text/event_src.jsonl` — 추출 기준(보호). `tools/extract_event.py work/unpacked text/event_src.jsonl`로만 다시 만든다.
  `tests/test_extract_event.py`가 커밋본과 새 추출이 같은지 확인한다.
- `text/event_ko.jsonl` — `{id, sha1, ko, state}`. `sha1`은 번역 당시 원문 기준값, 다르면 빌드 실패.
  배치는 `tools/ko_merge.py SRC KO BATCH.json [--replace]`로 넣는다(덮어쓰기는 `--replace`일 때만).
- 상태: `in_progress` → `needs_review`(초벌 완료) → `reviewed`(독립 검수 에이전트 대조 완료, D1) → `distribution_eligible`(게임 화면 QA까지 통과) / `needs_human_review`.
  검수 결과는 `tools/review_merge.py`로 넣는다(같은 원문·같은 번역의 반복 블록에 전파).

## 소비자 제약 (검사 `tools/mes.py check`)
| 규칙 | 근거 |
|---|---|
| ASCII `,` 는 음성 구간 구분자 — 개수 그대로, 문장 쉼표는 `，` | `0x13DBF8`/`0x24A570` |
| `#` 금지 (그 뒤는 주석) | `0x24AC50` |
| 줄을 영문자·숫자로 시작하지 않기 (라벨로 읽힘) | `0x13DA10` |
| 한 줄 255바이트, 블록 본문 합계 1023바이트 | 줄 버퍼 0x100, 본문 스택 버퍼 0x400 |
| `@n` 은 표시 줄바꿈, 파일 줄바꿈은 무시됨 | 본문을 구분자 없이 이어붙임 |
| 표시 줄 19칸 이하(이름 변수는 4칸), 음성 구간당 3줄 이하 | PoC3 화면 + 원문 최대치 |
| 이름 변수 `$OKA$` 등은 같은 종류·개수 유지 | 확장 루프 `0x13E3D0` |

## 표기
- 세로쓰기 유지(D5): `「」`, `『』`, `…`, `？`, `！`, `～` 는 전각 그대로. 말한 사람 표시 `치코「…」` 형식 유지.
- 띄어쓰기는 ASCII 공백. 대사는 빌드에서 `@s10 @s20`으로 바꿔 반 칸으로 그린다(검사는 1칸으로 셈).
- 이름 변수 뒤 조사는 `받침형（무받침형）`으로 쓴다: `$OKA$은（는）`, `$OTO$이（가）`, `$MOK$을（를）`,
  `$GEN$과（와）`, `$PAN$으로（로）`, `$KYO$아（야）`, `$NIY$이랑（랑）`. 훅(`0x13E4C8`)이 이름 끝 글자의
  받침으로 하나를 고른다(받침 ㄹ이면 `으X（X）`는 X). 각 형태는 1–3자/0–3자, 이름 바로 뒤에 붙여 쓴다.
  이름이 한글이 아니면 `은（는）` 그대로 보인다.

# 시스템 텍스트 문체·폭 (D11·D12, 2026-11-12)

플레이 테스트에서 메뉴가 일본어 구조를 그대로 옮긴 번역투이고, 가로 창을 넘치는 줄이 나왔다.

## 문체
- 한국 게임 UI에서 실제로 쓰는 말로 쓴다. 뜻·정보·말투(존댓말/반말)·고유명사(D7)는 유지한다.
- 선택지·메뉴 항목: 짧은 명사형이나 「~하기」. 예) `自動的に次の年に進む / 入力を待って次の年に進む` → `자동으로 넘기기 / 버튼을 누르면 넘기기`(×「자동으로 다음 해로」).
- 확인 질문: `~할까요?` 꼴. 예) `ゲームを続けますか？` → `계속할까요?`.
- 도움말 한 줄(MEMO 등): 「~합니다」나 명사형으로 짧게. 예) `子供の様子や写真などを見る` → `아이 모습과 사진을 봅니다`.
- 설명문(책·학교·직업 소개): 원문 말투를 살리되 한국어 어순으로. 「~의」 연쇄, 직역 한자어(`배속처`, `결정됩니다`), 「~해 버리다」 남용을 피한다.
- `%s` 뒤에 받침에 따라 바뀌는 조사를 쓰지 않는다(시스템 텍스트에는 조사 훅이 없어 `이（가）`가 그대로 보인다). 받침과 무관한 조사(`의`, `에게`, `도`, `만`, `에서`)를 쓰거나 문장을 바꾼다. `第%s子` → `%s번째 아이`.

## 폭 (`tools/width.py`)
- 칸 = 전각·한글 1, ASCII(공백 포함, 공백은 반 칸으로 그리는 전제) 0.5, 레이아웃 코드·`%s` 0.
- 표시 줄(`@n`)마다 원문 가장 긴 줄보다 넓지 않게, 줄 수는 원문 이하. `@n` 위치는 옮겨도 된다.
- 여러 파일에서 같은 일본어 항목(학교·책·직업·동아리 이름 등)은 조회 키일 수 있어 모든 파일에서 같은 한국어로 둔다.
- 바이트 제한 칸(`linetext.FIELD_BYTES`, 빌드가 검사): `school.txt` 정식 이름(3번째 칸)은 26바이트(한글·전각 2, ASCII 1) 이하. 넘으면 학교 선택 메뉴가 26바이트에서 잘라 `@e0`이 「퐈e0」처럼 깨져 보인다.
